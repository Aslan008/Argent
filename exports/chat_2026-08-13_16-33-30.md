## 1. Timezone: `Кызылорда (зима)` → `UTC+05:00`

**Причина**: `strftime('%Z')` возвращает локализованное имя timezone из Windows. На этой системе оно `"Кызылорда (зима)"` — это полное имя таймзоны `Asia/Qyzylorda` в Windows. Казахстан отменил DST в 2023, поэтому "(зима)" — просто часть имени, не сезонный индикатор. Код не виноват — он читал то, что Windows отдавала.

**Фикс** (`agent.py` строка 389-390):
```python
# Было:
_tz = _now.astimezone().strftime('%Z') or 'local'
# Стало:
_offset = _now.astimezone().strftime('%z')  # '+0500'
_tz = f"UTC{_offset[:3]}:{_offset[3:]}" if _offset else 'local'  # 'UTC+05:00'
```

UTC offset не локализован, не содержит мусора, однозначно определяет часовую зону.

## 2. Auto-detect для `\n` в инструментах

**Причина**: `_maybe_unescape_content` конвертировала литерал `\n` (backslash+n) в реальный newline, когда в тексте не было реальных newline. Это нужно для маленьких моделей, которые не умеют JSON-эскейпить. Но когда модель редактирует код с `\n` внутри строкового литерала (например `print("hello\nworld")`), unescape ломал синтаксис.

**Фикс** — auto-detect: после unescape проверяем, не сломал ли он кавычки. Если любая строка результата имеет нечётное количество неэскейпленных кавычек — unescape откатывается:

```python
candidate = text.replace("\\n", "\n").replace("\\t", "\t").replace("\\\\", "\\")
for line in candidate.splitlines():
    quotes = 0
    i = 0
    while i < len(line):
        if line[i] == '\\' and i + 1 < len(line):
            i += 2  # skip escaped char
            continue
        if line[i] in ('"', "'"):
            quotes += 1
        i += 1
    if quotes % 2 != 0:
        return text  # odd quotes → broken string literal → don't unescape
return candidate
```

Также заменил агрессивную `normalize` в `multi_replace_in_file_chunk` на `_maybe_unescape_content` + `.strip()` — теперь target comparison тоже использует auto-detect.

**Логика**:
- `print("hello\nworld")` → после unescape: `print("hello` (1 кавычка — нечётно) → **не unescape** ✓
- `line1\nline2` → после unescape: `line1` (0 кавычек), `line2` (0) → **unescape** ✓
- `x = "hello"\ny = "world"` → после unescape: `x = "hello"` (2 — чётно), `y = "world"` (2 — чётно) → **unescape** ✓

### 🤖 Argent
Не бесполезен, но ниша узкая. У него есть два свойства, которых нет у альтернатив:

**1. Последовательность для одного файла.** `multi_replace_in_file` вызывает `replace_in_file` в цикле — каждая следующая правка видит результат предыдущей. Если вызвать `replace_in_file` параллельно для одного файла — race condition: обе правки читают одинаковый snapshot, вторая перезатирает первую.

**2. Один round-trip для разных файлов.** 3 файла → 1 tool call вместо 3. Экономия токенов на обёрточном JSON.

Но на практике:

- **Несколько правок в одном файле** → `multi_replace_in_file_chunk` (есть syntax validation, откат при ошибке)
- **Правки в разных файлах** → параллельные `replace_in_file` (система поддерживает batch calls в одном ответе)

Единственный сценарий, где `multi_replace_in_file` незаменим — несколько text-based правок в одном файле без номеров строк. Это бывает, но редко, и обычно удобнее прочитать файл и использовать chunk.

Вердикт: не бесполезен, но дублирует функциональность. Если убрать — потеря минимальна. Оставить — лишний инструмент в реестре, который увеличивает cognitive load модели при выборе.

## Найденные проблемы

### 🔴 Баги

**1. `multi_replace_in_file` не в `_EDIT_TOOLS`** — external change detection не работает для него. Уже в плане удаления.

**2. `multi_replace_in_file_chunk` нет в `CORE_CHAT_TOOLS`** — маленькие модели не имеют инструмента, который system prompt им рекомендует. Уже в плане.

**3. `move_file` — нет RAG update** — после перемещения файла старый путь остаётся в векторном индексе, новый не добавляется. `semantic_search` будет возвращать сниппеты из несуществующего файла.

**4. `copy_file` — нет RAG update** — копия не индексируется, `semantic_search` не найдёт.

**5. `copy_file` — нет plugin path restriction** — может скопировать файл в `plugins/` директорию, обходя ограничение.

**6. `move_file` — plugin restriction только на source** — destination не проверяется. Можно переместить файл в `plugins/`.

### 🟡 Пропущенные фичи

**7. `multi_replace_in_file_chunk` — нет RAG update** — после правки файл не переиндексируется. Уже в плане.

**8. `multi_replace_in_file_chunk` — нет changed region preview** — модель не видит результат. Уже в плане.

**9. `multi_replace_in_file_chunk` — нет fuzzy matching** — маленькие модели с сломанным whitespace получают ошибку вместо авто-исправления. Уже в плане.

**10. `move_file` — нет snapshot** — нельзя откатить через file_tracker.

**11. `replace_python_function` — нет `_maybe_unescape_content` на `new_code`** — модель, отправляющая `\n` как literal backslash-n (а не newline), получит сломанный код. `replace_in_file` и `write_file` пропускают контент через unescape, `replace_python_function` — нет.

### 🟢 Дизайн-решения (не баги, но стоит подтвердить)
