# Инструкция агенту-генератору данных

Ты создаёшь обучающие примеры для Leeth — небольшой модели, которая принимает решения: выбирает вариант из списка,
отвечает «да/нет» с вероятностью, ставит оценку по шкале, находит фрагменты текста. Модель не пишет текст, она только
решает. Твои примеры — единственное, из чего она узнает, как решать правильно. Ошибка в метке учит модель ошибаться.

## Процесс

1. Возьми из `queue/` файл с наименьшим номером (`B0001.md`, `B0002.md`, …).
2. Прочитай его целиком и спецификацию задания, на которую он ссылается (`requests/R00X_*.md`), и `FORMAT.md`.
3. Создай примеры **строго по таблице плана** в пакете: одна строка плана = один пример, тот же `id`, `family`, `lang`,
   `ptype`, `group`, длина `state` в указанных пределах (считай слова!), правильный ответ — тот, что указан в плане.
   Скрипт приёма проверяет каждую строку по плану и отклоняет несовпадения. Длинные тексты не сокращай.
4. Запиши их в `incoming/<имя пакета>.jsonl` — одна JSON-строка на пример, кодировка UTF-8, без комментариев и без
   обрамления ```json.
5. Перепроверь каждую строку (раздел «Самопроверка»), исправь ошибки.
6. Перенеси файл пакета в `queue/done/`. Переходи к следующему.

Не меняй файлы в `requests/`, `FORMAT.md`, `AGENT.md`. Не читай и не создавай ничего за пределами этой папки.
Не запускай программы, кроме записи файлов.

## Правила качества (важнее количества)

- **Метка должна быть бесспорной.** Если разумный внимательный человек мог бы ответить иначе — перепиши пример так, чтобы
  ответ стал однозначным, или поставь вероятность (для «да/нет») ближе к 0.5, честно отражая сомнение.
- **Разнообразие.** Не повторяй структуру предложений, имена, числа, порядок вариантов из примера к примеру. Каждый пример —
  новая ситуация. Меняй длину: от одной фразы до нескольких абзацев (когда пакет просит длинный контекст — до указанного объёма).
- **Правильный ответ не должен угадываться по форме.** Он не всегда первый, не всегда самый длинный, не всегда содержит
  слова из вопроса. Неправильные варианты — правдоподобные, из той же области, а не очевидная чепуха.
- **Трудные случаи.** Не меньше трети примеров — «почти такие же, но с другим ответом»: одно слово, флаг, число или
  условие меняет решение. Именно на них модель учится различать.
- **Реализм.** Состояние (state) — то, что модель реально увидит: сообщение пользователя, лог, письмо, страница, команда,
  карточка товара, описание ситуации. Не пиши «Это пример для обучения».
- **Языки.** Пиши на языке, указанном для примера, естественно, как носитель; не переводи дословно с английского.
- **Никаких настоящих личных данных:** имена, адреса, телефоны, ключи, пароли — только вымышленные и явно неправдоподобные
  для реальных людей (например, домены `example.com`, `test.local`).

## Самопроверка каждой строки

- Это валидный JSON на одной строке; есть все обязательные поля (`FORMAT.md`).
- `answer` для choice — **дословно** один из вариантов; для multi — список вариантов (может быть пустым);
  для extract — **дословные** подстроки из `state`.
- Вариантов не больше 255, они не повторяются.
- Ответ верен. Перечитай state и вопрос ещё раз и реши заново, не глядя на свой ответ.
- `id` уникален: `<пакет>-<номер по порядку>`, например `B0007-012`.
