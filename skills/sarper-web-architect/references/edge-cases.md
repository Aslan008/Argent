# Что если: исключения и бюджет обращений

Этот файл — ветки принятия решений для скилла `sarper-web-architect`.
Читай его, когда `get_status`, `start_task` или `wait_task` вернули ошибку,
веб-ИИ ответил пусто/не по делу, закончился лимит, отключилось расширение или
неясно, какой домен/режим выбрать.

**Правило:** для каждой ситуации есть триггер, действие и условие остановки.
Если ни один вариант не подошёл — остановись и спроси пользователя, а не жги
лимит повторными запросами. Сработавшую ветку и её результат запиши в
`.argent/artifacts/<slug>_web_plan.md`.

| Ситуация | Признак | Что делать |
|---|---|---|
| **Закончился бесплатный лимит** | `wait_task`/`get_task` вернул `error`, `quota`, `rate_limit`, `429`, «limit reached» | Не повторять тот же запрос. Попробовать **другой домен** из `domains` (один раз). Если все недоступны — сохранить план в артефакт, сказать пользователю и продолжить локально **только** с его согласия. |
| **Доступен более умный режим/модель** | в `get_status` виден домен; модель поддерживает thinking; ответ поверхностный | Для архитектуры и сложных ошибок ставить `reasoning_level="high"` (и при необходимости `model`). Если ответ всё равно слабый — один retry с `high`, затем другой домен. **Не понижать** режим молча ради экономии. |
| **Неясно, какую модель/веб-ИИ выбрать** | пользователь не указал; несколько доменов в `get_status` | Приоритет: явный выбор пользователя → `domains_seen`/конфиг → `["gemini","claude","chatgpt"]`. Выбранный домен и модель записать в артефакт. Спрашивать пользователя только если варианты реально различаются по цене/качеству. |
| **Расширение/Chrome отключились** | `extension_connected=false`, MCP-ошибка соединения | Остановиться, попросить открыть Chrome/Sarper и вкладку. Не выдумывать ответ. После переподключения — `get_status`, затем продолжить с сохранённого брифа. |
| **Авторизация/вход истёк** | веб-ИИ показывает login, `auth`, пустой ответ | Попросить пользователя войти. Не отправлять задачу повторно, пока вход не восстановлен. |
| **Веб-ИИ отвечает не по делу / отказ** | ответ не содержит плана, уходит в сторону | Один раз переформулировать: сузить задачу, перечислить ограничения, попросить ровно 3 пункта. Если снова — сменить домен или спросить пользователя. |
| **Ответ слишком большой / код в Bag** | `Bag ID`, тысячи строк | Не копировать всё. Прочитать нужный блок `read_bag_content`, применить минимальный фрагмент; `write_bag_to_file` — только после проверки пути. |
| **Веб-ИИ противоречит проекту** | совет ломает существующий код/тесты | Локальные факты и тесты важнее. Один запрос на согласование: «в проекте X, твой совет даёт Y; как совместить?». Если ответ не подходит — локальный fallback. |
| **Контекст потерян / несколько вкладок** | ответ не помнит предыдущий план | `fresh=true` + сжатый бриф из артефакта. Не пересылать всю переписку. |
| **Sarper недоступен совсем** | `get_status` не отвечает; пользователь не хочет его запускать | Сказать прямо: «работаю без веб-ИИ», продолжить локально. Не имитировать консультацию. |
| **Локальная модель застряла** | 3 попытки без прогресса | Остановиться, показать пользователю точную ошибку и что пробовали; спросить: сменить подход, домен или сделать вручную. |
| **В запросе оказались секреты** | токен/пароль/`.env` в брифе | Не отправлять. Вырезать, заменить на `<redacted>`, при сомнении — спросить пользователя. |
| **Закончилось время/сессия** | долгий `wait_task`, пользователь уходит | Сохранить `task_id`, бриф и текущий план в артефакт; при возврате — `get_task`, не начинать заново. |

## Бюджет обращений

- **1 основная консультация** на этап/фичу + **1 уточнение**.
- **Не более 3 error-эскалаций** на одну ошибку; потом остановка и вопрос
  пользователю.
- `reasoning_level="high"` — для архитектуры, интерфейсов и сложных ошибок.
  Для рутинных уточнений допустим `medium`, но **не** снижай его молча, если
  ответ уже оказался слабым.
- Каждый выбор домена/модели/режима и каждый `task_id` фиксируй в
  `.argent/artifacts/<slug>_web_plan.md`, чтобы после перезапуска не начинать
  с нуля.

## Быстрый порядок при сбое

1. Остановись и классифицируй: лимит / сеть / авторизация / качество ответа /
   контекст / локальная ошибка.
2. Найди строку в таблице и выполни **только её** действие.
3. Если после одного разрешённого retry прогресса нет — не зацикливайся;
   вернись к пользователю с фактами.
