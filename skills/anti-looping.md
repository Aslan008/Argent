# Skill: ANTI-LOOPING (Против зацикливания)

## Задача

Не застревать в петлях из повторяющихся вызов инструментов без прогресса.

## Триггеры заклинчивания

- 2+ одинаковых вызова одного и того же инструмента с тем же результатом.
- Повтор одного действия в надежде, что результат изменится.
- Ожидание события, который нельзя проверить (GUI без консоли, «успех» без подтверждения).

## Правило остановки
>
> 1 неудача = проанализировать ошибку и СМЕНИТЬ подход.
> 2 одинаковых вызова без прогресса = немедленно сменить стратегию или канал.

## Алгоритм при 403/404/500/таймауте/пустом body

1. Первый non-2xx = стоп-сигнал (не «плохо загруженная страница»).
2. Не повторять browser_get_content / reload / open над тем же URL.
3. Сменить канал:
   - browser_open заново (если была сессия)
   - browser_reload (только один раз, после осознания)
   - search_web / read_webpage (публичные ресурсы)
   - run_command с curl / Invoke-WebRequest (raw-ответ)
4. Проверить доступ ДО запроса контента: cred'ы (базовая авторизация), правильный путь/порт.
5. Если нужен доступ, которого нет: сообщить пользователю, что нужно, и попросить уточнение.

## Алгоритм для LSP (_hierarchy/_references/_implementations)

1. Сначала find_definition на нужной строке -> точный column.
2. Только потом _hierarchy /_references / _implementations.
3. Никогда не вызывать find_references/find_implementations без предварительного find_definition.

## Алгоритм при двусмысленности

- Не гадать. Использовать ask_user_questions с вариантами.

## Проверка вместо заявления

- Объявлять задачу только после реальной проверки (тест/сборка/команда).
- Привязывать фактический вывод, не «exit code 0».

## Запрещено

- Повторять один и тот же вызов «пока не сработает».
- Давать placeholder-фразы («No response requested», «N/A») без объяснения.
- Останавливаться без проверки результата.
