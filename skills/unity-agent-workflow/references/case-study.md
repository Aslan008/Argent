# Разбор реальной работы: система травы Grassy (Unity 6.4, URP 17.4)

Как агент сделал крупную доработку (AAA-план: тени, средний план, земля под травой, качество,
настройки игры) и затем копирование/вставку полей — без окна Unity. Что запускалось, когда и зачем.

## Вторая задача: копирование/вставка полей и слоёв

1. Прочитал, как устроены кнопки слоёв и отложенные действия редактора (`_deferredAction` — модальные
   окна и правки вне layout-прохода) — новые кнопки сделаны по тому же образцу.
2. Выяснил, что у поля относится к «месту» (террейн, сетка чанков, карты, запечка) — это при вставке
   не переносится. Список составлен по реальным полям класса (awk по объявлениям), а не по памяти.
3. Решение для «вставить настройки, кроме…»: JSON в буфере → временный **выключенный** скрытый объект
   (`HideAndDontSave`, без OnEnable — без GPU) → копирование `SerializedProperty` с исключениями → Undo.
4. dotnet-проверка → batchmode-компиляция → **тест** `_ClipTest_TEMP` в batchmode:
   - первый прогон упал: `Kernel 'GenerateGrass' not found` — пересоздание травы на выключенном поле
     в `-nographics`. Это был реальный недочёт → добавлена проверка `isActiveAndEnabled`;
   - второй: 6/7 OK, «отмена» FAIL — оказалось, ошибка теста (операции в одной группе Undo).
     Добавил `Undo.IncrementCurrentGroup()` и контрольную проверку «Undo вообще работает» → 8/8 OK.
5. Удалил тест, обновил документацию системы, отчёт: «логика проверена тестом в batchmode, меню руками
   в окне не прокликивал, вставка карт тестом не покрыта».

## Чему это учит
- **Каждой проверке — свой инструмент**: dotnet — опечатки, batchmode — правда о компиляции,
  тест — логика, снимок — вид, бенчмарк — цена.
- **Тест тоже может быть неправ.** FAIL — повод проверить и код, и тест; фактические значения в строке
  FAIL экономят прогон.
- **Ложные срабатывания инструментов** (устаревшие DLL и .csproj) — знать и перепроверять вторым способом.
- **Отчёт с границами проверки** («не проверял руками») — пользователь знает, что ещё посмотреть.
