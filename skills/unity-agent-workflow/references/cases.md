## 1. Проект и запуск Unity

**Что если Unity открыт у пользователя (Temp/UnityLockfile занят)?**
Второй экземпляр на тот же проект не запустится или испортит `Library/`. Варианты:
- ограничиться `fast_check.py` (он Unity не требует) и сказать, что финальная проверка в Unity не сделана;
- попросить пользователя закрыть Unity, или
- `unity_batch.py --wait 900` — если проект занят *другим агентом/тестом* и скоро освободится
  (видно по процессам: `tasklist | findstr Unity` / `ps aux | grep Unity`).
Если в среде есть MCP к открытому редактору — используй его вместо batchmode.

**Что если lock-файл есть, а Unity не запущен?** После падения Unity файл остаётся. На Windows
`unity_batch.py` проверяет, занят ли файл, а не только его наличие, — свободный не мешает.
Удалять `Temp/` вручную не нужно.

**Что если Unity.exe не найден?** Версия — из `ProjectSettings/ProjectVersion.txt`. Пути Hub:
Windows `C:\Program Files\Unity\Hub\Editor\<ver>\Editor\Unity.exe` (или из
`%APPDATA%\UnityHub\secondaryInstallPath.json`), macOS `/Applications/Unity/Hub/Editor/<ver>/Unity.app/Contents/MacOS/Unity`,
Linux `~/Unity/Hub/Editor/<ver>/Editor/Unity`. Иначе — `--unity <путь>` или `UNITY_EXE`.
Нет нужной версии — не запускать другой: смена версии переимпортирует/апгрейдит проект. Сказать пользователю.

**Что если batchmode завис / идёт очень долго?** Первый запуск после большого изменения
(новые пакеты, смена платформы, удалённый Library) — переимпорт, бывает 10–40 минут. Смотри хвост лога:
`tail -f <log>` — если строки идут (Importing, Compiling) — ждать. Если тишина > 5 мин — вероятно, модальное
окно (в batchmode его нет, но бывает ожидание лицензии/сети) → `--timeout`, затем разбор лога.

**Что если «No valid Unity Editor license»?** Batchmode требует активированную лицензию (Hub должен быть
залогинен; Personal тоже подходит). Агент это не чинит — сообщить пользователю.

**Что если `-quit` завершает Unity раньше, чем мой метод закончил?** С `-executeMethod` Unity выходит
после возврата из метода. Асинхронное (`EditorApplication.update`, `delayCall`, `AsyncGPUReadback` с
колбэком) не успеет. Решение: делать синхронно, либо `--no-quit` и вызывать `EditorApplication.Exit(code)`
самому в конце (бенчмарк-шаблон так и делает).

**Что если нужен Android/iOS-таргет?** `-- -buildTarget Android` — но переключение платформы
переимпортирует ассеты (долго) и меняет `Library/`. Делать только по необходимости и предупредить.

## 2. Компиляция C#

**Что если `fast_check` показывает ошибку, а Unity — нет (или наоборот)?**
- fast_check ругается, Unity нет: `.asmref`, `versionDefines`, `defineConstraints`, файлы с
  `#if` под платформу, кодоген. Верь Unity, но выясни причину.
- Unity ругается, fast_check нет: кодоген (FishNet/Mirror weaving, Burst, Entities), ошибки
  `[SerializeField]`-атрибутов, ошибки в другой сборке, которую fast_check не собирал (`--all`).
- Если fast_check ссылается на **устаревшую DLL** из `Library/ScriptAssemblies` (видно по пути в ошибке) —
  у этой сборки нет своего `.csproj`; нужна проверка Unity.

**Что если «тип не найден», хотя класс существует?** Почти всегда — границы asmdef:
код в asmdef не видит `Assembly-CSharp` (скрипты без asmdef). Решения: перенести зависимость в asmdef,
добавить ссылку в `references` asmdef, или «мост» — класс в Assembly-CSharp, который видит обе стороны
(подписка на событие/статический хук через `[RuntimeInitializeOnLoadMethod]`). Editor-код (`UnityEditor`)
не должен попадать в рантайм-сборку: папка `Editor/` или `#if UNITY_EDITOR`.

**Что если в логе `error CS` из файла, который я не трогал?** Проверь `git status`/`git diff` — возможно,
чужая незавершённая работа. Не чини чужое молча: сообщи. Если ошибка мешает проверить твоё — скажи об этом прямо.

**Что если ошибки только в `Library/PackageCache/...`?** Несовместимость версии пакета с Unity или
сломанный кэш. Не правь кэш (перезапишется). Сообщи; крайняя мера — удалить конкретную папку пакета
в `Library/PackageCache` (переустановится при запуске).

**Что если после правки всё «скомпилировалось», но поле не появилось в инспекторе?**
Не сериализуется: `private` без `[SerializeField]`, свойство вместо поля, тип не `[Serializable]`,
`static`/`readonly`, `Dictionary`. Или у компонента свой `CustomEditor`, который рисует поля вручную —
тогда поле надо добавить и в редактор (ищи `FindProperty("соседнее_поле")`).

## 3. Шейдеры и графика

**Что если «Kernel 'X' not found» / compute не работает в тесте?** Это `-nographics` (нет GPU).
Для логики — создавать объект выключенным и не трогать GPU; для рендера — `--graphics`.

**Что если шейдер скомпилировался в batchmode, но розовый в игре?** Варианты под другой API/платформу,
`multi_compile` с ключом, который включается только в рантайме, SRP Batcher-несовместимость CBUFFER.
Проверка: `--graphics` + снимок кадра с включённой фичей. Ищи в логе `Shader error in '<имя>'`.

**Что если надо поменять Shader Graph?** Это JSON (несколько объектов подряд, ссылки по `m_ObjectId`).
Правка вручную возможна, но рискованна: узлы, рёбра, слоты должны совпадать. Перед правкой — **резервная копия**
рядом (вне Assets или с расширением, которое Unity не импортирует, например `.bak`). После — `unity_batch.py --graphics`
и проверка, что граф открывается (импорт без ошибок). См. unity-files.md.

**Что если нужен глобальный параметр для шейдеров (карта, вектор)?** `Shader.SetGlobalTexture/Vector`
из C# + объявление в шейдере. Учти, что в редакторе без Play Mode этот код должен вызываться в
`[ExecuteAlways]`-компоненте, иначе в Scene View параметра не будет.

## 4. Тесты в batchmode

**Что если тест упал, но код, похоже, верный?** Проверь сам тест: в первом прогоне этой работы
«отмена» падала, потому что несколько операций попали в одну группу Undo — тест был неправ.
Печатай фактические значения в строке FAIL — так видно сразу.

**Что если компонент в тесте бросает исключения из OnEnable/Update?** `[ExecuteAlways]`-компоненты в
редакторе живут: OnEnable зовётся при AddComponent на активном объекте. Создай GameObject, сразу
`SetActive(false)`, потом AddComponent — OnEnable не вызовется.

**Что если нужен Update/корутины/физика?** В batchmode без Play Mode их нет. Варианты: вызвать
метод рефлексией N раз; `Physics.Simulate(dt)` вручную (при `Physics.simulationMode = Script`);
или Unity Test Framework PlayMode-тесты (`-runTests -testPlatform PlayMode`).

**Что если тесту нужна сцена проекта?** `EditorSceneManager.OpenScene(path)` — и **не сохранять**.
Нельзя, если пользователь держит сцену открытой с несохранёнными изменениями — но тогда и Unity открыт,
а batchmode всё равно невозможен.

**Что если тест создал ассеты (текстуры, .asset)?** Писать их во временную папку внутри `Assets/`
(например `Assets/_AgentTemp/`) и удалить папку с `.meta` после. Или `AssetDatabase.DeleteAsset` в конце теста.

## 5. Ассеты, сцены, ссылки

**Что если надо узнать, где используется ассет/скрипт?** `unity_find.py refs <путь>` — поиск GUID по
текстовым ассетам. Ссылки из кода (`Resources.Load("...")`, ключи Addressables, строки) — grep по коду.

**Что если «Missing Script» в сцене?** У скрипта сменился GUID (удалили `.meta`, пересоздали файл)
или класс переименован так, что имя файла ≠ имя класса. `unity_find.py scene` покажет
`Missing?` с GUID → `unity_find.py path <guid>`. Лечение: вернуть старый `.meta` из git
(`git show HEAD:путь.meta`).

**Что если я случайно удалил `.meta`?** Немедленно восстановить из git (`git checkout -- файл.meta`) **до**
запуска Unity: при импорте Unity создаст новый GUID и все ссылки на ассет порвутся.

**Что если правка сцены нужна, а Unity закрыт?** Предпочтительно — editor-скрипт через `-executeMethod`:
`OpenScene` → изменения через API → `MarkSceneDirty` → `SaveScene`. Это меняет сцену пользователя —
только если это и есть задача, и с упоминанием в отчёте. Ручная правка YAML — для мелочей
(значение поля), не для структуры (новые объекты требуют корректных fileID).

**Что если ассет огромный (bake-данные, террейн, сцена 5 МБ)?** Не читать целиком: `grep -n`,
`unity_find.py scene --filter`, `head -c`. Двоичные ассеты (`.asset` с `m_` бинарными блоками,
текстуры, меши FBX) не править текстом.

## 6. Производительность и замеры

**Что если цифры прыгают между прогонами?** batchmode шумит: прогрев 60–90 кадров, 3 серии, медиана.
Повторить замер «базы» в том же запуске. Сравнивать разницы, а не абсолюты. Не делать выводов из < 5 %.

**Что если надо понять, во что упирается кадр?** Отключать подсистемы по одной в одном запуске
(тени, слой, эффект) и смотреть дельту. Счётчики (draw calls, видимые объекты) — из собственной статистики
системы или `UnityStats` (только в редакторе с графикой).

**Что если снимок чёрный/пустой?** `-nographics`, камера без `targetTexture`, URP без камеры в стеке,
не было прогрева (ленивые загрузки), или читаешь `RenderTexture` до завершения рендера.

## 7. Git и чужая работа

**Что если в `git status` много чужих изменений?** Это нормально — пользователь работает параллельно.
Не откатывать, не форматировать, не включать в свой отчёт как свои. Свои файлы перечислить явно.

**Что если пользователь просит откатить «всё, как было»?** Откатывай только свои изменения этой сессии,
по списку; чужое — нет. Перед `git checkout`/`reset` — показать, что будет потеряно.

**Что если хочется закоммитить?** Только по просьбе. Большие bake-ассеты (>100 МБ) — проверить LFS/.gitignore.

## 8. Когда честно остановиться и спросить

- Нужна лицензия, логин, другая версия Unity, закрытие редактора пользователем.
- Задача требует правки общих настроек проекта (URP Asset, Quality, Player, Input) без явного разрешения.
- Непонятно, чья незавершённая работа ломает компиляцию.
- Визуальное решение «на вкус» (цвет, стиль) — показать снимок и спросить.
