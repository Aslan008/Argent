Жесткий линейный конвейер План + Трассировка (Dry Run) + Код для локальных и компактных ИИ-моделей (7B-32B). Экономит контекстное окно, исключает угадывание архитектуры на лету и заставляет модель заполнить строгий технический трафарет перед написанием кода.



Instructions

Plan-Simulate-Code Local

Линейный низкоуровневый протокол для локальных и компактных моделей. Заменяет абстрактные рассуждения заполнением жесткого текстового трафарета контрактов и пошаговой трассировкой переменных перед генерацией кода.



When to Use

Любая задача по написанию, модификации, рефакторингу или отладке кода при работе через локальную или малую модель.

Пошаговая реализация кода по готовому чертежу от старшей модели (plan-sim-pro) или напрямую по задаче пользователя.

Steps

Read Context First (Никаких догадок): Прочитай целевые файлы перед планированием. Строго запрещено выдумывать имена функций, классов, полей или импортов, которых нет в текущем контексте.



Fill the Simulation Stencil (Заполни жесткий трафарет): До написания первой строчки кода выведи заполненный технический трафарет строго по шаблону ниже. Запрещено пропускать пункты или писать общие фразы вместо конкретных типов и значений:



\### 1. TARGET FILES

\- \[MODIFY/CREATE] path/to/file.ext : какая именно функция или класс меняется



\### 2. DATA CONTRACTS

\- Signature: exactFunctionName(param1: Type, param2: Type) -> ReturnType

\- Mutated State: точные имена изменяемых переменных, полей или таблиц



\### 3. DRY-RUN TRACE

\- Step 1: \[Input: конкретное значение] -> \[Action: вызов/операция] -> \[Output: точный результат]

\- Step 2: \[Input от Step 1] -> \[Action: вызов/операция] -> \[Output: точный результат]

\- Crash Test 1 (Null / Empty / Invalid): какое значение сломает Step 1-2 -> какое условие проверки нужно

\- Crash Test 2 (Failed Call / State Error): что произойдет при ошибке на Step 2 -> как вернуть или сохранить валидное состояние



\### 4. PRE-CODE FIX

\- Список конкретных проверок (guard clauses, try/catch, доп. аргументы), которые нужно включить в код по итогам Crash Test

Atomic Implementation (Атомарная реализация): Переходи к коду только после заполнения всех 4 блоков трафарета:



Пиши код строго по сигнатурам из 2. DATA CONTRACTS с обязательным включением защитных проверок из 4. PRE-CODE FIX.

Если задача затрагивает более 2 файлов или требует более 150 строк кода, остановись после вывода трафарета и пиши код по одному файлу за итерацию, чтобы избежать потери внимания.

Выводи полный рабочий код изменяемых функций без сокращений вроде // ... rest of logic here внутри меняющихся блоков.

Gotchas

Никогда не меняй типы аргументов или структуру возвращаемых данных прямо посреди генерации кода. Все контракты фиксируются заранее в блоке 2. DATA CONTRACTS.

В блоке 3. DRY-RUN TRACE запрещены размытые формулировки вроде "проверим входные данные" или "обработаем ошибку". Пиши конкретные примеры значений (например: user\_id = None -> raise ValueError до обращения к БД).

Не подключай внешние библиотеки и не вызывай методы, которые не существуют в прочитанных файлах проекта.
