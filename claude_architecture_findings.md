# Архитектура Claude Desktop & Claude Code: Инструменты, Режимы Мышления и UltraCode

> Документ составлен на основе реверс-инжиниринга боевого рантайма приложения Claude (`app.asar` / `.vite/build`) с помощью REA. Предназначен для адаптации передовых архитектурных решений в собственного агента **Argent**.

## ЧАСТЬ 1. Архитектура исполнения инструментов (Tools Runtime)

Вскрытые компоненты:
* `ptyHostWorker.js` — воркер выполнения терминальных команд (`Bash`);
* `directMcpHost.js` — хост вызовов и маршрутизации инструментов MCP;
* `nodeHost.js` — среда изоляции подпроцессов и перехвата stdio.

### 1. Выполнение команд через псевдотерминал (PTY) с очисткой ANSI
* **Проблема обычных агентов:** `subprocess.Popen("cmd.exe", stdout=PIPE)` намертво зависает на интерактивных командах (git credentials, npx prompts) и забивает контекст escape-последовательностями `\x1B[32m`.
* **Решение Claude:** 
  * Использование псевдотерминала (`node-pty` / ConPTY на Windows). Команды выполняются как в реальной консоли.
  * Встроенная конечная машина состояний (FSM) парсера VT100: состояния `GROUND`, `ESCAPE`, `CSI`, `OSC`, `DCS`. Все цвета и управляющие символы фильтруются на лету, отдавая модели идеально чистый текст.

### 2. Скроллбэк, ротация и Grep на потоке вывода
* Вывод команд не накапливается бесконечно в памяти. Он ротируется сегментами по **4 МБ** (`segmentMaxChars: 4194304`, максимум 16 сегментов).
* Размер возвращаемого модели окна вывода жёстко лимитирован **100 КБ** (`W = 102400`), чтобы исключить раздувание контекста (token blowout).
* Если вывод огромен, Claude активирует встроенный поиск `grepResult()`, отдавая модели только строки вокруг совпадений (`±2` строки контекста) с номерами строк.

### 3. Живая цензура секретов (Live Redactor)
* В потоковом буфере работает класс `SecretRedactor`.
* Он проверяет исходящий текст и заменяет обнаруженные токены/ключи на `*`, даже если секрет разбит по границе двух смежных сетевых или файловых чанков.

### 4. Древовидное завершение процессов на Windows (Tree-Kill)
* Обычный `process.kill()` на Windows убивает только родителя, оставляя висеть дочерние процессы (например, `python`, `git`, `node`).
* Claude выполняет жесткое завершение всего дерева:
  ```javascript
  spawnSync("C:\\Windows\\System32\\taskkill.exe", ["/pid", pid, "/T", "/F"], { windowsHide: true });
  ```

### 5. Мягкая обработка ошибок MCP (`isError: true`)
* При ошибках инструмента Claude не роняет сессию и не кидает фатальных исключений:
  ```javascript
  try {
      return await f.callTool({ name, arguments });
  } catch (err) {
      return {
          content: [{ type: "text", text: `Tool call failed: ${err.message}` }],
          isError: true
      };
  }
  ```
  Модель видит причину неудачи как штатный результат шага и способна сама исправить аргументы на следующей итерации.

## ЧАСТЬ 2. Режимы мышления и архитектура UltraCode

Вскрытые компоненты:
* `index.chunk-DVtu79Rf.js` — таблицы моделей, уровни усилий (`effortLevel`), словари настроек;
* `index.chunk-BaivF2vS.js` — спецификация и переключатели `ultracode`;
* `index.chunk-DFe6MQAC.js` — Remote Control API и управление токенами размышления.

### 1. Иерархия мышления в Claude

В рантайме Claude разделены два понятия: **Режим мышления (`thinking_mode`)** и **Уровень усилий (`effort_level`)**:

#### Режимы мышления (`thinking_mode`):
1. **`off`** (значение 3) — размышление отключено полностью (для простых моделей или быстрых ответов).
2. **`auto`** (значение 2) — модель сама динамически решает, когда и сколько думать, в зависимости от сложности задачи.
3. **`extended`** (значение 1) — принудительное глубокое рассуждение на каждом запросе.

#### Уровни усилий (`effort_level`):
```javascript
settings_vocabulary: {
  effort_level: {
    low: 1,      // Быстрые ответы на простые вопросы
    medium: 2,   // Сбалансированный режим для повседневных задач
    high: 3,     // Глубокий анализ (рекомендован по умолчанию для кода)
    xhigh: 4,    // Экстра: комплексные архитектурные задачи
    max: 5       // Предельные задачи (максимальный расход лимитов)
  }
}
```

* `low`: минимальный бюджет токенов, отсекает длинные внутренние цепочки рассуждений.
* `medium`: стандартные инженерные задачи.
* `high`: рекомендуется для кода. Включает многоуровневый анализ крайних случаев.
* `xhigh` / `Extra`: углублённое исследование сложных зависимостей.
* `max`: сессионный режим (не сохраняется в конфиге). Снимает большинство внутренних ограничителей бюджета, предупреждает пользователя: *"May use excessive tokens resulting in long response times"*.

### 2. Что такое UltraCode на самом деле?

В коде Claude **`ultracode` — это НЕ просто ползунок количества токенов.** Это **совершенно другой режим оркестрации агента**:

```javascript
ultracode: () => F().optional().catch(void 0).describe(
  "Enable ultracode for the session: standing dynamic-workflow orchestration at any effort level. " +
  "Session-scoped — typically provided via --settings or the apply_flag_settings control request; " +
  "interactive toggles never persist it. Requires workflows to be enabled and a model that supports ultracode."
)
```

#### Что физически происходит при включении `ultracode`:
1. **Принудительный форсинг усилий на максимум:**
   ```javascript
   if (e.findLast((e => e.settings?.ultracode !== void 0))?.settings?.ultracode === true) {
       return { ...t, default: "xhigh" };
   }
   ```
   Активация `ultracode` мгновенно поднимает базовый уровень усилий мышления до `xhigh`.
2. **Активация мета-инструмента `Workflow Tool`:**
   Агент переключается из линейного режима «вопрос-ответ-тул» в режим **динамического пайплайна (Dynamic Workflow Orchestration)**: задача декомпозируется на независимые подзадачи со своими контрольными точками.
3. **Подключение серверного советника (`advisorModel`):**
   В рантайме активируется отдельный серверный инструмент `Advisor Tool`, который параллельно валидирует шаги основного агента и подсказывает оптимизации.
4. **Ключевой триггер (`workflowKeywordTriggerEnabled`):**
   Если в пользовательском промпте присутствует ключевое слово `"ultracode"`, агент автоматически переключает текущий ход (turn) на использование движка `Workflow Tool`.
5. **Взаимный сброс:**
   Если сессия находится в режиме `ultracode`, а пользователь вручную меняет уровень мышления через переключатель `effortLevel`, флаг `ultracode` сбрасывается в `false`, возвращая агента в обычный режим.

## Рекомендации для архитектуры Argent

1. **Разделить управление мышлением в Argent:**
   * Сделать параметры `thinking_mode` (`off` / `auto` / `extended`) и `effort_level` (`low`, `medium`, `high`, `max`), транслируя их в соответствующие поля целевых провайдеров (`reasoning_effort` для OpenAI/OpenRouter или `thinking.budget_tokens` для Claude).
2. **Реализовать аналог UltraCode через Workflow Mode:**
   * Создать режим оркестрации, при котором Argent не просто вызывает модель, а создаёт план с промежуточными чекпоинтами (Planner + Executor + Critic), поднимая уровень reasoning до максимума.
3. **Ограничить размер вывода команд до 100 КБ:**
   * Защитить контекст Argent от переполнения длинными логами компиляции и тестов с добавлением предупреждения о сокращении вывода.
