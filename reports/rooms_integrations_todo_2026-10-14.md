# Комнаты: MCP, скиллы, плагины, Leeth, все инструменты Argent, редактор уровня n8n

Список ведётся по ходу работы: пункт отмечается `[x]` сразу, как только он сделан и проверен тестом.
Принцип: никаких костылей — всё через те же модель данных, валидатор и движок; без сети и модели
всё проверяется тестами с подставными исполнителями.

## A. Модель и движок

- [x] A1. Тип шага `mcp`: сервер, инструмент, аргументы (`{{поле}}`), `sets`, `confirm`, `retries`; сервер поднимается из конфигурации по требованию
- [x] A2. Тип шага `skill`: прочитать скилл целиком в поле состояния, с исключением разделов (`ignore`)
- [x] A3. Агентный шаг: `skills` (подмешать инструкции скиллов), `mcp` (какие серверы доступны), `ignore` (что игнорировать)
- [x] A4. Политика «что игнорировать» (`mcp:сервер.инструмент*`, `skill:имя`, `skill:имя#Раздел`) — единый модуль, реально проверяется в `call_mcp_tool` / `list_mcp_tools` / `read_skill` / `list_skills`
- [x] A5. Тип шага `plugin`: команда плагина `command_*` или событие хука; вывод в состояние
- [x] A6. Тип шага `leeth`: делегировать задачу, отфильтровать список по критерию, разложить по категориям, прочитать страницу/форму
- [x] A7. Все инструменты Argent доступны шагу `tool` (проверка по реестру) и агентному шагу; Leeth-инструменты не в запрещённых
- [x] A8. Расширенные `sets`: `json:путь`, `regex:шаблон`, `lines`, `count`, `first_line`, `int`, `float`, `bool`
- [x] A9. Шаг `foreach` (по списку из поля, переменная, индекс, признак конца) — ограниченный
- [x] A10. Шаг `wait` (пауза в секундах, с потолком)
- [x] A11. Общие свойства шага: `disabled` (пропустить), `note` (заметка)
- [x] A12. Валидатор: ссылки на серверы/скиллы/плагины (предупреждения), синтаксис `ignore`, новые типы; `harden` конструктора: mcp/plugin/leeth требуют подтверждения
- [x] A13. `replayable` / журнал / подкомнаты / диаграммы (`diagram.py`) / доска (`board.py`) знают новые типы

## E. Дополнение владельца (2026-10-14, второе сообщение): правила комнаты, память, подсказки, ПК, параметры модели, циклы

Принцип прежний: всё через модель данных, валидатор и движок; опасное — только с защитой (задержка, отмена, спрашивать); честно сказать, чего нет.

- [x] E1. Правила комнаты (`rules`): запретить все инструменты (`no_tools`), запретить изменяющие (`read_only`), чёрный список (`deny_tools`), игнорирование MCP/скиллов для всей комнаты (`ignore`); проверка валидатором + защита на исполнении (в т. ч. у вложенных комнат — правила наследуются)
- [x] E2. Память комнаты: режим `isolated`/`shared` (агенты помнят, что делали прошлые шаги), блок `forget` (очистить память, подсказки и выбранные поля) — вызывается по условию стрелками
- [x] E3. Блок «Подсказка» (`hint`): текст для модели (следующему агенту / всем до очистки / выбранным шагам), подсказка у самого агента и у комнаты; встроенные счётчики `<шаг>_visits` и `_steps` для условий «зациклилось»
- [x] E4. Блок «Питание ПК» (`power`): выключить, перезагрузить, сон, гибернация, блокировка, выход, отмена — с задержкой не меньше 10 с, пробный режим, подтверждение
- [x] E5. Уведомления: текст может писать модель (`compose`); отчёт о доставке (Telegram / окно ПК / консоль); готовые пресеты в палитре
- [x] E6. Параметры модели (`sampling`) у агента и у комнаты: temperature, top_p, top_k, min_p, repeat_penalty, reasoning_effort, thinking_budget — реально доходят до провайдера
- [x] E7. Циклы: `loop` — for (диапазон), times (N раз), while, do-while, repeat-until, for-in (по словарю); `break` и `continue`; существующий `foreach` понимает break
