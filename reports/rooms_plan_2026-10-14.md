# Комнаты (Rooms): разбор и план доведения до финального вида — 2026-10-14

## 1. Что есть сейчас (src/rooms, ~1200 строк, 1325 строк тестов)

Декларативный движок «комнаты и рельсы»: комната = JSON-граф узлов (`tool`, `agent`, `condition`, `human_pause`,
`spawn_room`) с рёбрами `if / else / while(max)`; переходы решает движок по типизированному состоянию, а не модель;
агентный узел пишет в состояние только поля из своего `writes`; супервизор маршрутизирует между комнатами,
сбои уходят в `triage`; журнал write-ahead (intent/commit) даёт безопасное продолжение после падения.
Подключено одной командой `/rooms`.

## 2. Почему комнатами не пользуются (найдено при чтении кода)

| # | Дыра | Следствие |
|---|------|-----------|
| 1 | Запуск только руками: `/rooms <задача>`, старт всегда с `analyze`; нет `run <имя>`; модель не может позвать комнату | Никто не знает, зачем это нужно |
| 2 | В комплекте 3 комнаты (`analyze`, `debug_loop`, `triage`), все про одно | Мало полезных рецептов |
| 3 | `Budget.max_tokens` объявлен, но нигде не проверяется | «Жёсткий бюджет» — на словах |
| 4 | Статистика и карантин живут в памяти одного запуска (`build_library()` каждый раз новая) | Карантин не срабатывает никогда |
| 5 | `human_pause` завершает прогон: ответ человека записывается и выбрасывается | Нельзя спросить и продолжить |
| 6 | Проверка «тесты зелёные» делается агентом (`run_tests` — agent-узел), он же сообщает результат | Против принципа «verifier-first»: зелёное должен определять процесс, не слова |
| 7 | `debug_loop` делает `git commit -am` без вопроса | Опасный побочный эффект в автономном режиме |
| 8 | Нет подстановки параметров: инструкция узла не знает задачу пользователя | Комната не может быть переиспользуемым рецептом |
| 9 | У агентного узла нет своего набора инструментов/роли | Узел «исследуй» может писать файлы |
| 10 | Маршруты между комнатами зашиты в `default_routes()` в коде | Пользовательские комнаты нельзя связать в цепочку |
| 11 | Нет видимого прогресса, нет итогового отчёта, нет истории прогонов | Непонятно, что происходит и что получилось |
| 12 | Подсказки автодополнения для `/rooms` в cli_prompt описывают другое («возобновить сессию», «создание субагентов») | Путаница |
| 13 | Нет создания/удаления/проверки пользовательских комнат из интерфейса | Только ручной JSON |

## 3. Позиционирование

- `ultracode` — план «на лету» для большой нестандартной работы.
- **Комнаты — повторяемые именованные рецепты с рельсами**: «почини тесты», «сделай ревью», «проверь релиз»,
  «исследуй вопрос». Вердикты выносят процессы (код возврата команды), а не модель; каждый узел ограничен по
  шагам, токенам и времени; опасные шаги спрашивают человека.

## 4. План (порядок выполнения)

**A. Корректность и безопасность движка**
- A1. Бюджеты по-настоящему: токены (узел и комната), секунды (комната), учёт в `State.usage`.
- A2. Сохранение статистики/карантина (`.argent/rooms_stats.json`), снятие карантина командой.
- A3. `human_pause` продолжает прогон, если человек ответил и у узла есть рёбра.
- A4. Детерминированные проверки: `tool`-узел с `sets` (`ok`, `exit_code`, `tail`, `output` → поля состояния).
- A5. `confirm: true` — спросить человека перед выполнением узла (коммит и т. п.).

**B. Полезность**
- B1. Подстановка `{{поле}}` в instruction/args/prompt; `defaults` комнаты; `key=value` при запуске.
- B2. `role` и `tools` у агентного узла (читающий узел не пишет файлы).
- B3. `next` в самой комнате (цепочки комнат из данных); `default_routes()` остаётся для совместимости.
- B4. Выбор комнаты по задаче без LLM: `router.pick_room` (имя, описание, `tags`), при неуверенности — вопрос.
- B5. Новые стартовые комнаты: `fix_bug`, `code_review`, `implement_feature`, `research`, `release_check`,
  `explain_repo`; `debug_loop` переведён на проверку процессом + подтверждаемый коммит.
- B6. Итоговый отчёт прогона (что сделано/что не получилось/сколько ушло) и история `.argent/rooms_runs/`.

**C. Встраивание**
- C1. Инструмент `rooms` для модели (`list | show | run | resume | history`), запуск с подтверждением человека,
  скрыт в режиме плана для `run`/`resume`.
- C2. Прогресс: узлы комнаты в панели задач (как у ultracode) + строки в консоли.
- C3. `/rooms` целиком: `list`, `show`, `run`, `<задача>`, `resume`, `history`, `last`, `new`, `delete`,
  `validate`, `unquarantine`, `spawn`; исправленные подсказки автодополнения.
- C4. README (EN/RU), память проекта, тесты на всё новое.

## 5. Что намеренно не делаю
- Параллельные узлы/map: усложняют журнал и возобновление, выигрыш для текущих рецептов мал.

- Коммиты в git — не делаю (по правилу владельца).

## 6. Что сделано (всё из пп. A–C плана, плюс найденное по ходу)

**Движок.** Бюджеты проверяются по-настоящему (токены комнаты = дельта `State.usage`, секунды, шаги); внутри узла
`_consume_bounded` обрывает цикл по `max_tokens`. `human_pause` с ответом продолжает прогон (`into`,
`<into>_approved`); без ответа — пауза, как раньше. События `on_event` (node_start/node_end/room_end).
Прерванный агентный узел с read-only набором инструментов безопасно переигрывается при `resume`, остальные — к человеку.

**Узлы и данные.** `sets` (вердикт от процесса: `ok|exit_code|output|body|tail`), `confirm`, `role`, `tools`,
`{{поле}}`, `defaults`, `next`, `tags`, `report`; `run_command` получил `total_timeout` (потолок 300 с → до 4 ч для шага
тестов, в схему модели не выставлен).

**Библиотека.** 9 комнат: analyze, debug_loop, fix_bug, implement_feature, code_review, release_check, research,
explain_repo, triage. Статистика/карантин в `.argent/rooms_stats.json` (карантин — только для своих и ИИ-комнат,
стартовые считаются, но не карантинятся). triage теперь знает каталог комнат; `route_to` расходуется один раз.

**Использование.** `/rooms` целиком (`src/rooms/cli.py`): роутер по словам, run k=v, resume, last/history, new,
validate, delete, unquarantine, spawn, hint. Инструмент `rooms` для модели; строка-подсказка в хвосте запроса,
когда сообщение явно подходит к комнате (`/rooms hint off` выключает). Прогресс в панели задач и консоли, запись
каждого прогона, итоговый отчёт. Новый запуск спрашивает, если есть прерванный прогон (иначе он бы стёрся).

**Проверено.** tests: 240 по комнатам (было 121), полный прогон без leeth2 — 7545 passed; два падения в полном прогоне
не относятся к комнатам (Brave rate-limit — тайминг; telegram-метка инструмента — исправлена, тест зелёный).
Живого прогона с реальной моделью не было: исполнители в тестах — фейки, реальный реестр инструментов и
реальный `analyze_project` проверены дымовым запуском.

## 6а. Модульность (по запросу владельца: «как n8n», выбрано «чат, затем редактор»)

**Блоки.** К узлам tool/agent/condition/human_pause добавлены `set` (записать значения), `notify` (console/desktop/
telegram), `room` (подкомната: входы из состояния родителя, выходы копируются назад, имя выхода в `into`/`<id>_exit`,
глубина ≤3, токены суммируются); `retries` (0–5) и рёбра `on_error` (сообщение в `state.error`, узел в
`state.error_node`). Ссылки между комнатами проверяются (нет цели или цикл — комната не загружается/не добавляется;
удалить вызываемую комнату нельзя).

**Чат-конструктор** (`/rooms build <описание>`, `/rooms edit <комната> <правка>`, `rooms` build/edit для модели):
модель без инструментов выдаёт JSON комнаты, тот же валидатор + проверка ссылок, до 2 раундов исправления по тексту
ошибок, «домашние правила» (мутирующие инструменты получают `confirm`, `spawn_room` нельзя, имена стартовых заняты,
≤25 узлов), показ схемы (`/rooms diagram`, Mermaid) и подтверждение; правка стартовой комнаты сохраняется копией
`<имя>_custom`; цикл «Сохранить / Поправить словами / Отмена».

**Визуальный редактор** (`/rooms editor`, `/rooms editor stop`): страница без внешних ресурсов
(`src/rooms/editor/index.html`) + локальный сервер (`editor_server.py`): 127.0.0.1, случайный порт, случайный токен,
проверки Host/Origin, лимит тела 512 КБ, CSP; пишет только в каталог пользовательских комнат, через тот же валидатор;
стартовые комнаты только читаются (сохранение — копией); раскладка узлов лежит в `<имя>.layout`. На странице:
перетаскивание узлов, соединение, панель свойств по типу узла, рёбра always/if/else/while/on_error, живая проверка
(ошибки подсвечивают узлы), JSON-импорт/экспорт, Mermaid. Проверено в браузере: открытие, выбор, добавление узла,
соединение, сохранение копией стартовой, удаление; 30 тестов сервера.

**Гайд внутри редактора.** Кнопка «📖 Гайд» (F1 или «?»): 14 разделов — что такое комната, быстрый старт, карта экрана, все типы узлов с полями, переходы и циклы, состояние и {{поля}}, язык условий, лимиты, свойства комнаты, 5 готовых примеров (открываются кнопкой как несохранённая комната), расшифровка ошибок проверки, клавиши, запуск и отладка, словарь. Плюс контекстная справка в правой панели, легенда цветов, приветственная панель, подсказки под полями и порядок переходов кнопками ↑↓. Тесты следят, чтобы гайд не отставал от движка.

**Упрощение редактора.** Палитра блоков слева (новый шаг встаёт после выбранного и вставляется в цепочку), вкладки «Схема / Словами / JSON», правая панель с фразой «что делает этот шаг» простыми словами и свёрнутым «Дополнительно», таблицы «поле — значение» вместо JSON, конструктор условий без синтаксиса, вставка {{поля}} выбором, отмена/возврат, форма создания с шаблонами, сообщения проверки по-русски, гайд — выдвижная панель с подсветкой реальных кнопок.

## 7. Что осталось (честно)
- Запуск комнат по расписанию (режим «room» в автоматизациях `/tasks`) — не сделан: раннер автоматизаций работает в

  зависит от модели, поэтому всегда есть показ схемы и подтверждение.
- Живая проверка владельцем: `/rooms почини падающие тесты` на реальном проекте (подтверждения команд идут обычным
  потоком approval, поэтому автономность ограничена им).
- Токены агентных узлов — оценка по длине, не точный счёт провайдера.
- Параллельные узлы/map и выбор комнаты моделью не делались (см. п. 5).
- В `.argent/rooms_journal.jsonl` лежит старый прерванный прогон от 2026-07-05 (analyze/investigate): `/rooms resume`
  его продолжит (узел read-only, переиграется), а новый запуск сперва спросит.

## 9. Параллельные ветки, триггеры, примеры и выделение рамкой (дополнение того же дня)
Чек-лист: `reports/rooms_parallel_triggers_todo_2026-10-14.md`.

**Параллельные ветки со слиянием**
- Блоки `parallel` (развилка, до 8 веток, `workers`) и `join` (слияние: `merge` error/first/last/list, `wait_for` all/any,
  `on_branch_fail` fail/continue). Каждая ветка идёт со своей копией состояния в своём потоке; слияние детерминировано по
  порядку стрелок; бюджет шагов/токенов/времени общий; развилка — один шаг журнала (возобновление переигрывает её целиком,
  только если все блоки веток переигрываемы).
- Потокобезопасность: `run_scope.py` (область видимости ветки) для параметров модели и политики, блокировки на общие ресурсы
  (Leeth, страница, экран), блокировка подтверждений, потокоместные счётчики токенов и глубины подкомнат.
- Валидатор: 2–8 веток, ветки не пересекаются, каждая доходит до слияния, нет паузы человека внутри, вложенность ≤3,
  предупреждение, если ветки делят браузер/экран/Leeth.

**Триггеры**
- Расписание: режим автоматизации `room` (`/rooms schedule <комната> <когда>`), запуск без человека (`src/rooms/headless.py`):
  подтверждения отклоняются, пауза человека = статус «нужен человек», спавн комнат выключен.
- Webhook: `src/rooms/webhooks.py` — `POST /hook/<имя>` на 127.0.0.1:8731, секрет показывается один раз (хранится хеш),
  разрешены только объявленные параметры, лимит тела 64 КБ, один прогон на хук, ≤4 одновременных, троттлинг неверных
  секретов, проверка Host, `?wait=N` до 120 с, комната выполняется в дочернем процессе.
- Команды: `/rooms triggers [комната]`, `/rooms webhook <комната> [имя]`, `remove|on|off <имя>`; панель «Запуск по событию» в
  редакторе.

**Редактор и обучение**
- Выделение нескольких блоков рамкой зажатой ЛКМ на пустом месте (Shift/Ctrl — добавить); панорама — пробел, средняя или
  правая кнопка, Alt+ЛКМ.
- Поле «Зачем этот шаг» у любого блока. Гайд: разделы «Параллельные ветки», «Триггеры», путь обучения по примерам.
- Примеры: `ex_parallel_research` (веер + слияние), `ex_branching_task` (разветвление по результату), `ex_plan_critic_loop`
  (план → критик → правка → память → todo), `ex_full_pipeline` (33 блока: все возможности комнат в одном сценарии с
  пояснениями) + стартовая подкомната `critic_review`, которую можно ставить на место критика.

**Проверено вживую**
- Параллель на реальных инструментах (read_file / list_directory / grep) — три ветки пришли; два реальных вызова модели
  (OpenRouter) в параллельных ветках — 7,8 с против 9,5 с последовательно (холодный старт был 45 с).
- Webhook: реальный HTTP → дочерний процесс → комната, 200 за 0,7 с; неверный секрет → 404; статус сохранён.
