Задача владельца: проверить Argent полностью, найти ошибки, недочёты и пути развития, составить план и
выполнить его; затем полностью проверить и исправить ArgentMobile. Работа автономная, без коммитов.

## Как проверялось

- Полный прогон тестов Argent до и после правок (`.venv`, ~8500 тестов), тесты Rust TUI (`cargo test`, 528).
- Линтер ruff по реальным ошибкам (неопределённые имена, затенённые определения, мёртвые присваивания).
- Список ошибок владельца `Desktop/Ошибки в Argent.txt` (29.09) — каждый пункт сверен с текущим кодом.
- Реальные логи `~/.argent/logs` (agent, providers, trimmer) — что ломается в живой работе.
- `doctor` на реальном окружении.
- Живые проверки: запуск браузера через `BrowserEngine` с расширением Stagehand; ArgentMobile в браузере
  против локального mock-сервера OpenAI API (поток, ошибка в потоке, «Стоп» + новый вопрос, настройки).
- Мобильный нативный код: Java скомпилирован javac (android.jar + заглушки Capacitor), C++ проверен MSVC
  `/Zs` с заглушками JNI/llama.h. Собрать APK нельзя: на машине нет NDK и исходников llama.cpp, а скачивать
  без слова владельца я не стал.

### Найдено при аудите

- **Сжатие на несуществующей модели**: логи за недели — `/aux`-модель удалена (`qwen2.5-3b-instruct not found`,
  Z.ai «Unknown Model»), каждое сжатие уходило в детерминированную выжимку. Теперь при отказе
  вспомогательной модели сжатие выполняет основная.
- **Крошечные модели и длинный ход**: `sliding_window_trim` при ходе больше окна делал аварийный сброс —
  все шаги задачи терялись. Теперь остаются запрос и последние шаги, ранние уходят в архив журнала.
- **Окно сервера узнаётся заранее**: KoboldCPP (`/api/extra/true_max_context_length`) и llama-server
  (`/props`) опрашиваются в начале хода; окно в настройках больше серверного — уменьшается с заметкой.
- **`read_webpage` возвращал страницу ошибки Chrome** («Не удается получить доступ к сайту») как
  содержимое сайта: результат навигации резервного браузера не проверялся.
- **Версии комнат**: два сохранения в одну миллисекунду давали `-2.json`, который сортировался раньше
  оригинала — «новые сверху» ломалось (тест падал нестабильно). Теперь порядковый номер в имени.
- **Затенённые тесты**: два класса/функции с одинаковыми именами — первые не запускались. Воскресший тест
  BM25 сразу упал: ошибка в арифметике самого теста (15 слов, не 14), код верен.
- Юнит-тесты `read_webpage` запускали настоящий Chromium — изолированы.
- Индикатор контекста считал каталог инструментов слабых моделей нулём.
- Мелочи: мёртвые присваивания, `text_codec` в пакете (`pyproject.toml`).

## ArgentMobile: найдено и исправлено

- **Service Worker не работал вовсе**: в `public/sw.js` стоял TypeScript (`as Promise<Response>`) —
  синтаксическая ошибка (подтверждено `node --check`). Переписан: только свой домен, «сначала сеть» для
  страниц (раньше «сначала кэш» навсегда закрепил бы старую версию), кэш для `/assets/*`; в APK и на
  dev-сервере не регистрируется.
- **Гонка ответов**: прерванный «Стопом» ответ продолжал писать в пузырь СЛЕДУЮЩЕГО ответа и вставал в
  историю после нового вопроса. Теперь у каждого ответа своё состояние; ответ встаёт за своим вопросом и в
  свой диалог. Проверено в браузере.
- **История не подрезалась**: длинный диалог переполнял окно; на телефоне (llama.cpp, 2048) это падение на
  первом шаге с ложным «повреждён файл модели». Подгонка под окно (облако 32k, WebLLM 4096, GGUF 2048/4096/
  8192 на выбор) + заметка над ответом; в JNI отдельный код «промпт длиннее окна» и остановка при заполнении
  окна; подряд идущие сообщения одной роли склеиваются (строгие шаблоны Gemma/Mistral).
- **Ошибка посреди потока** (`{"error":...}`, OpenRouter) молча пропускалась → «0 токенов». Разбор SSE
  вынесен в `sse.ts`: ошибки, `data:[DONE]` без пробела, хвост без перевода строки, `reasoning` (OpenRouter/
  Ollama) — всё с тестами.
- **Эмодзи роняли debug-APK**: `NewStringUTF` требует «Modified UTF-8» (CheckJNI abort), `GetStringUTFChars`
  портил эмодзи в промпте. Переход через `byte[]`/`String(bytes, UTF-8)`.
- **Шаблон чата GGUF**: ChatML был зашит в код (ломал Llama 3/Gemma/Phi). Теперь `llama_chat_apply_template`
  с шаблоном из метаданных модели, ChatML — запасной вариант.
- **Домашняя Ollama из APK не работала**: cleartext HTTP запрещён Android 9+, а со страницы `https://localhost`
  — mixed content. `usesCleartextTraffic` + `allowMixedContent`.
- **«Скачать» и «Экспорт» в APK ничего не делали** (WebView игнорирует `<a download>` с blob). Новый
  нативный плагин `ArgentFiles` (MediaStore → «Загрузки/Argent»). Копирование работает и вне HTTPS.
- **Настройки**: открытие окна само подменяло модель и включало оффлайн (автоскан); ввод пути по буквам
  сохранялся и переключал режим; с GGUF нельзя было вернуться на модель WebLLM; обработчик провайдера
  навешивался при каждом открытии; слияние настроек было мелким (новые поля терялись у обновившихся).
- **Честные подписи**: «Helio G99 ARM NEON» показывалось везде, даже для облака. Подпись теперь по режиму,
  движок сохраняется в сообщении.
- Веб-заглушка автопилота отвечала «успешно» на всё («Приложение открыто», хотя ничего не было).
  Автопилот выбирает приложение по точному имени, а не первому «содержит».
- Убрана молчаливая подмена модели «единственным .gguf в Загрузках»; повторная загрузка модели учитывает
  смену потоков/окна; COEP `credentialless` (шрифты Google блокировались); highlight.js — только частые
  языки: основной бандл 1083 → 273 КБ.
- Тесты: `npm run check` (типы + тесты SSE, окна контекста, настроек, выбора движка, парсера тегов);
  проверены мутацией.

## Что осталось и пути развития

**Требует владельца**
1. Пересобрать APK (нужны Android NDK и `llama.cpp` в `android/app/src/main/cpp/llama.cpp`; затем
   `npm run build && npx cap sync android && gradlew assembleDebug`). Нативные правки (UTF-8, окно,
   шаблон чата, `ArgentFiles`) проверены компилятором только с заглушками.
2. Для картинок в Ornith на KoboldCPP — запуск с `--mmproj` (файл проектора из GGUF-репозитория модели).
3. Живая проверка сжатия длинного хода на вашей KoboldCPP/llama-server.
4. Коммит изменений (я не коммитил: в прошлых сессиях — только по просьбе).

**Развитие Argent**
- Разделить монолиты `agent.py` (~3200 строк), `browser_engine.py` (~3250), `providers.py` (~1950):
  цикл хода, обработка ошибок провайдера и сборка запроса — отдельные модули с тестами.
- Калибровка оценки токенов по ответам сервера (`n_prompt_tokens` из 400 / tokenize для длинных текстов).
- Предложение поднять окно, если сервер запущен с большим, чем в настройках (сейчас — только понижение).

**Развитие ArgentMobile**
- Режим «Argent на ПК»: телефон как клиент настольного Argent (инструменты, комнаты, память), а не голой
  модели — через мост, как у Telegram.
- Автопилот как инструменты модели (сейчас — только фиксированные команды «открой/домой/назад»).
- Хранение диалогов в IndexedDB вместо localStorage (лимит ~5 МБ).
