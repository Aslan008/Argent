# Решение: Replay + agent bench (выбрано)

**Дата:** 2026-10-23  
**Статус:** выбрано как следующее крупное направление. Реализация ещё не начата; этот файл фиксирует договорённости, чтобы не потерять контекст.

## Что строим

Петлю «запись → просмотр → воспроизведение → измерение»:

1. **Trace** — журнал прогона рядом с сессией: шаги, инструменты, аргументы/результаты (клипованные и с редакцией секретов), тайминги, токены, чекпоинты, модель/провайдер, cwd и git HEAD.
2. **Replay** — просмотр прогона как процесса, а не только переписки: шаги, инструменты, ошибки, стоимость/время, раскрытие деталей.
3. **Bench** — воспроизводимые кейсы из реальных задач: стартовый чекпоинт/коммит, запрос, проверки, лимиты; запуск в отдельном `git worktree`; отчёт pass/time/tokens/diff.
4. **Bench miner** — сканер сессий: ошибки инструментов, правки пользователя, откаты, повторные команды → черновики кейсов на подтверждение человеку.

## Три режима (не смешивать)

- **Trace replay** — чтение записи; детерминирован.
- **Counterfactual replay / fork** — восстановить чекпоинт и продолжить с другого шага другой моделью/промптом; это эксперимент, не «повтор».
- **Exact replay** — кэш ответов провайдера по хэшу запроса; для отладки harness/UI, не для оценки модели.

## Опора в проекте

- `argent/session.py` — сообщения, модель, провайдер, cwd.
- `src/agent/checkpoints.py` — git-снимки вне ветки (`refs/argent/checkpoints/*`), можно поднимать в `git worktree`.
- `src/agent/history_replay.py` — уже умеет собирать блоки из сохранённых сообщений; использовать как fallback и основу отображения.
- `src/bridge/events.py` — стабильные события `tool_start/tool_end/checkpoint/diff/usage/done`.
- `.argent/transcripts`, `compact_log.jsonl`, Leeth-траектории — дополнительные источники.

## Первый вертикальный срез

1. Trace для новых сессий (минимальный набор событий).
2. `replay` по одной реальной сессии: таймлайн + детали инструментов.
3. Один кейс из этой сессии: чекпоинт → worktree → прогон → проверка.
4. Тот же кейс на второй модели; отчёт «прошёл/не прошёл, за сколько».

## Метрики

- pass@1 по проверкам;
- время и токены на кейс;
- число tool calls и повторных ошибок;
- размер diff;
- вмешательства человека.

## Риски

- Replay не равен повторной генерации — разделять режимы в UI и документации.
- Никогда не проигрывать write/run слепо: worktree, таймауты, запрет сети по умолчанию, подтверждение разрушительного.
- Секреты: редакция, локальное хранение, opt-in.
- Объём: клиповать, ротировать, хранить хэши и ссылки.
- Качество кейсов: проверки из проекта или подтверждённые человеком; иначе bench измеряет бессмысленное.
